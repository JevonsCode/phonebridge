# PhoneBridge 多设备与双向恢复设计

状态：设计稿；不代表多对多已经实现。当前 Flutter 桌面、统一品牌和稳定 MCP 交付继续，乱码作为当前版本缺陷修复。用户已授权自主设计、开发和测试，不再增加重复审批。

## 目标与当前差距

让用户从设备名称直接连接自己的手机和电脑，不找 IP、不重新扫码；一台电脑可同时管理多部手机，一部手机可记住并保持与多台电脑的连接。恢复操作从任何一端发起。

已核对当前代码：
- `bridge/src/hub.ts` 只有一个 phone、pending 和 busy；第二部手机返回 409。
- `BridgeSession.kt` 只有一个 WebSocket；`TrustedComputers.kt` 保存多个电脑，但 activeId 仅选一个。
- 手机已有“启动电脑服务”，调用 `DesktopServiceRecovery.kt` → Supervisor 的 `POST /service/start`。这要求电脑上的 Supervisor 仍可达。
- 当前桌面进程与后台 Supervisor 分开；关闭桌面窗口不应停止手机连接。
- Windows 网卡名称乱码修复数据读取编码，不能靠替换为问号、隐藏名称或改变系统区域设置。

## 方案选择

1. **推荐：多对多连接，每部手机独立选择当前控制者。** 电脑可并行操作不同手机；不同电脑可连接同一手机，但只有当前控制任务能读屏和操作它。任务之间可交接，不重复配对。
2. 多个已保存配对但仅一条在线连接：改动少，不过电脑无法及时知道手机是否在线，切换也更慢。作为旧协议兼容模式。
3. 多台电脑任意同时点击同一手机：不采用。手机只有一个前台界面，交错指令会破坏双方工作流程，即使每条点击串行也不能解决。

无需云账号，不建立公开控制入口。第一阶段使用同一可达网络；远程网络通过已配置的私有网络连接，自动发现不承诺跨网段。公网中转、远程开机和通用电脑远控不在本次范围。

## 两端界面

电脑首页改为“我的手机”列表；卡片显示用户命名、型号、在线状态和正在执行的任务，示例“工作手机 · 可连接”“备用手机 · MacBook 正在使用”。点击打开该手机详情，主按钮按状态显示“连接”“恢复连接”“启动手机连接”。多手机时，每个详情页和任务始终固定目标，不能因为切换 UI 卡片改变运行中 AI 的目标。

手机首页改为“我的电脑”列表；每张卡片显示名称、连接状态和是否正在控制本机。示例“家中电脑 · 正在控制”“MacBook · 已连接”“办公室电脑 · 离线”。卡片主按钮按状态显示“连接”“启动电脑服务”“切换到这台电脑”。用户可以重命名、忘记单个设备；只断开目标设备，不影响其他设备。

两端顶部显示简短汇总，例如“2 部手机在线”“已连接 2 台电脑”。新增设备入口放在列表末尾。无需展示端口、令牌、租约等实现字段；IP 放在详情中的网络信息，仅供排障。沿用当前 Flutter 字体、圆角、蓝色操作按钮和中英文本地化。

首次使用：自动发现附近运行 PhoneBridge 的设备，选名称并确认一次；已记住设备下次自动连接。发现失败时保留扫码及手动地址作为备用入口。发现消息只能提供候选地址，实际连接必须验证已保存的设备身份；同名电脑不能覆盖旧设备。

## 双向启动与恢复

“启动服务”与“启动电脑”分开表述。电脑登录后轻量 Supervisor 自动运行，主 Hub 可按需重启；手机的无障碍连接服务存活时保留轻量管理通道。屏幕操作通道和管理通道分离，主操作会话中断不应同时失去恢复入口。

| 实际状态 | 手机发起 | 电脑发起 |
|---|---|---|
| 两端后台在线，操作会话未建立 | 连接指定电脑 | 连接指定手机 |
| 电脑 Hub 停止，Supervisor 在线 | 启动电脑服务，等待就绪并连接 | 启动本机服务 |
| 手机管理通道在线，操作会话断开 | 恢复连接 | 请求手机恢复指定会话 |
| 对端暂时不可达 | 显示离线、上次在线时间，可重试 | 同左 |
| 手机应用被系统强行停止或无障碍被关闭 | 本机提示打开应用或恢复权限 | 显示具体原因；已插 USB 且 ADB 已授权时可打开应用 |
| 电脑关机、休眠或 Supervisor 也停止 | 显示电脑不可达，需要电脑恢复运行 | 本机启动客户端可恢复服务 |

如果管理通道完全消失，无法凭网络请求启动没有接收者的进程。不能显示虚假成功。关机、休眠、断网仅能在有明确证据时细分，否则统一“暂时无法连接”。Android 不承诺被强行停止后还能远程唤起；USB 打开只作为已授权设备上的可用辅助，并不充当网络功能。

“暂停操作”保留管理连接但不接收读屏/操作。明确“断开连接”暂停对应设备自动重连；新的用户连接动作才恢复它。关闭桌面窗口保持后台服务。不同故障使用可操作的文案，不统一显示无限 Reconnecting。

## 设备身份和路由

- 本地生成稳定随机 `computerId` / `deviceId`，不使用 IP、型号、序列号作为身份；重命名、换 Wi-Fi、升级保持 ID。
- 每对电脑/手机保留独立关系和凭据，继续使用已有安全存储，不让用户手动管理。忘记一部手机仅撤销该关系。
- Hub 使用 `Map<deviceId, DeviceSession>`；每个手机有独立连接、心跳、排队状态和日志上下文。一部手机超时只影响该手机。
- Android 使用连接管理器维护已启用电脑的管理通道，重用现有无障碍执行器；执行器只接受当前控制者和任务的指令。
- Supervisor 保留服务启动入口，允许该电脑的已配对手机启动 PhoneBridge Hub；不接受任意进程名、命令行或脚本。
- 设备发现只更新经过身份验证的候选地址。退避重连加抖动，避免多设备同时反复启动服务。每个目标的启动请求幂等，成功条件是服务就绪而非 HTTP 请求已发出。

## 同一手机的任务交接

手机端是最终控制权仲裁者，因为不同电脑的 Hub 无法彼此可靠协调。

`controlSession = { computerId, agentSessionId, epoch, expiresAt }`，获取空闲手机自动成功；UI 操作或 MCP 一次任务使用同一 session。心跳维护租期，建议间隔 10 秒、失联 30 秒释放；使用手机单调时钟计时。无需每次点确认。

当前任务占用时，其他电脑可以查看设备状态，但不能读屏或插入点击，返回“这部手机正在被 MacBook 使用”。用户在手机点击“切换到这台电脑”可交接：停止接收旧任务的新指令；让当前已派发操作结束或取消并记录结果；递增 epoch、清除旧节点快照，再允许新任务观察和执行。若已派发操作的结果不确定，标为 unknown，不补发。租期过期同样不能跳过执行器的单操作栅栏。

`acquire_control(deviceId)` 为每次任务生成随机 agentSessionId，并返回不透明 taskHandle；它不等于 MCP 进程或传输连接 ID。每次读屏、操作、续期、释放显式携带 taskHandle，服务端解析为固定 deviceId 与 epoch。共享同一 MCP 进程的两个聊天也持有不同句柄，不共享选中目标。不同手机拥有独立控制权，因此可真正并行执行。

AI 任务结束调用 `release_control(taskHandle)`；MCP 进程关闭释放属于它的句柄。不能假设 MCP 协议本身提供聊天结束事件。任务最近一次有效操作后最多空闲 60 秒，管理通道心跳或进程存活不会延长此空闲期；后台推理超过此时间需重新取得控制权并重新观察。30 秒连接租期与 60 秒任务空闲期分别约束失联及遗忘释放，正在执行的指令仍受执行器栅栏保护。旧句柄返回已过期，不悄悄生成新任务重放操作。

## MCP 与操作日志

MCP 的安装命令继续使用固定入口，不随设备数量或版本变化。新增 `list_devices` / `acquire_control(deviceId)` / `release_control(taskHandle)`，用取得任务句柄完成设备选择，不设置进程级全局选中手机。AI 可读状态和最近日志。

新协议操作请求携带 taskHandle，服务端固定关联 `deviceId` 和 controlSession；不把“最后打开的 UI 卡片”当全局目标。仅有一部已配对手机时取得控制权可省略 deviceId，但操作仍携带返回的句柄；存在多部手机时，AI 必须选择目标，歧义时列出设备而非猜测。目标断线不自动切到另一部手机。旧协议工具仍按旧的一对一连接运行，不能复用新协议中的任意活动任务。

原有日志继续保留，新增 computerId、deviceId、agentSessionId、epoch、requestId、操作名、时间、耗时、状态及错误。恢复服务、取得/释放控制权、交接同样记事件。手机保存本机跨电脑操作的有界日志；每台电脑保存自己派发的日志。按事件 ID 去重；离线期间的日志同步不会重放操作。AI 可按设备、电脑、时间读取；保留已约定的文本脱敏，不记录凭据。

## 迁移与兼容

现有加密配对、名称、允许操作、白名单和主动暂停全部保留。增加 schema version，先写旁路文件并验证，再原子替换，失败保留原始记录。首次升级给现有记录分配稳定 ID，不要求用户重新配对。

旧协议继续一对一。新旧双方先协商 capabilities；只有双方支持身份绑定和多设备协议时才启用多对多。旧配对共享令牌在兼容通道中保留；升级时通过已认证旧会话协商独立关系凭据，成功落盘并得到双方确认后才启用新路径。无协商能力或失败时仍走旧模式，不猜测旧手机身份，也不拿型号区分。

同一旧共享凭据可能已由多部手机保存，因此不能以“第一个连接者”为依据独占迁移或撤销旧令牌。兼容连接逐个升级，并明确展示协议旧版本的单连接限制。新协议下重复 deviceId 不覆盖活动会话；同身份重连应经过旧会话关闭或会话代次校验。

旧共享凭据无法精准撤销一部设备：迁移完成的独立关系可以单独忘记；如果被忘记设备可能仍持有旧共享凭据，必须关闭本电脑的旧兼容入口并撤销旧凭据。界面在这一操作前说明“仍使用旧版连接的其他手机需要升级并重新连接”，新协议独立关系保持。不可默默保留可重新迁移的旧入口，同时声称已经撤销。正常升级不触发这一撤销流程；全部旧关系迁移后关闭旧入口。

## 分阶段验收

1. 当前版本收尾：修复中文网卡编码和旧桌面后台复用；验证新桌面显示固定 MCP 入口，当前配对保持。
2. 电脑支持多手机：Hub 分设备会话、独立凭据和日志、MCP 显式选设备、桌面列表；模拟两部手机并行，断开一部不影响另一部。
3. 手机支持多电脑在线：管理通道、手机端控制权、双向恢复、列表；模拟两台电脑竞争同一手机，确保旧 epoch 和旧节点不能操作。
4. 发现与迁移：验证 Wi-Fi/IP 变化、同名设备、旧配对升级失败回退、中英文状态和无障碍/后台被停止时的诚实提示。

发布前需要：实际手机与两台独立电脑切换、两部实际手机接同一电脑、Hub 停止后从手机启动、手机操作连接停止后从电脑恢复。当前只有一部真机时，第二部模拟测试必须标明，不能写成多真机验收完成。Mac 实机由用户验收，Windows 本机先验。多对多以独立后续版本交付，不把尚未实现的功能写进当前 0.6.1 下载说明。
