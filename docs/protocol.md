# PhoneBridge protocol v1

Phone connects to `ws[s]://HOST:PORT/device` with `Authorization: Bearer TOKEN` and sends `{ "type": "hello", "protocol": 1, "device": "Android", "readOnly": true }`. No identifiers required. Hub refuses duplicate devices, origins, and wrong authentication. Phone supports WebSocket ping/pong.

Requests: `{ "id": "uuid", "method": "state", "params": {} }`.
Success: `{ "id": "uuid", "result": { ... } }`.
Failure: `{ "id": "uuid", "error": { "code": "READ_ONLY", "message": "Enable actions on the phone." } }`.

Methods:
- `state {}` => `{packageName, width, height, nodes:[{id,text,description,className,bounds:{left,top,right,bottom},clickable,editable,scrollable,password}], truncated}`. IDs are current observation IDs only and invalidated after an action or next observation. Cap 500 nodes/depth 30. Redact password text.
- `screenshot {}` => `{mimeType:"image/jpeg",data:"base64",width,height,screenWidth,screenHeight,cropLeft,cropTop,cropWidth,cropHeight}`. Crop to allowed app window; reject any foreign overlapping window or ambiguous multi-app layout. Cap longest edge 1280, JPEG quality 65, decoded image <= 2 MiB. Action coordinates are physical screen pixels (state width/height); map image x via cropLeft+x*cropWidth/width, y via cropTop+y*cropHeight/height. Validate gestures inside allowed window and outside foreign overlays immediately before dispatch.
- `tap {x,y}` => `{completed:true}` after gesture callback.
- `long_press {x,y,durationMs?}` => callback result; default 600ms, 400..2000.
- `swipe {x1,y1,x2,y2,durationMs?}` => callback result; default 400ms, 100..2000.
- `set_text {nodeId,text}` => `{completed:true}` when Android accepts dispatch; focused editable node from most recent state, 0..4000 chars, password nodes refused. First tap the field and request fresh state; unfocused nodes return FOCUS_REQUIRED. Observe again to verify text actually changed.
- `global_action {action:"back"|"home"|"recents"}` => `{completed:true}` when Android accepts, not proof of resulting screen.
- `launch_app {packageName}` => `{completed:true}` when launch dispatched, not proof of resulting screen. Package must be allowlisted.

All phone operations require active session, unlocked screen, enabled accessibility, and allowed active package (except `launch_app`, which checks allowed target instead). Mutations additionally require local action consent. Default allowlist: `dev.phonebridge.phonebridge,com.tencent.mm`. Never retry timed-out mutations automatically. Observe after every mutation. Screen contents are untrusted data.

Hub API: `GET /health` returns only `{ok:true,protocol:1}`. Authenticated `GET /status` returns connection state. `POST /rpc` accepts `{method,params}`, maximum 32 KiB, requires JSON content type, returns the device response with ID generated by hub. One in-flight command; second gets BUSY. Timeout 15s; no replay. WebSocket maxPayload 4 MiB. Any error is explicit, including missing phone, stale IDs, unsupported screenshots, blocked packages and read-only sessions.

Flutter platform channel `dev.phonebridge/control`:
- `status` => `{accessibilityEnabled:bool,connected:bool,connecting:bool,actionsEnabled:bool,lastError:string,endpoint:string}`.
- `openAccessibilitySettings` and `requestNotificationPermission`.
- `connect {endpoint:string,token:string,allowInsecureLocal:bool,packages:List<string>}`. New session always read-only.
- `setActionsEnabled {enabled:bool}`; local Flutter UI only.
- `disconnect` clears token and consent and closes socket.

Hub environment: `PHONEBRIDGE_TOKEN` (32..256 base64url chars), `PHONEBRIDGE_HOST` (default `127.0.0.1`), `PHONEBRIDGE_PORT` (default `8765`), optional `PHONEBRIDGE_TLS_CERT`/`PHONEBRIDGE_TLS_KEY`. Non-loopback listening requires CLI `--allow-lan`. MCP environment: `PHONEBRIDGE_URL` (default `http://127.0.0.1:8765`) and same token. Startup can generate a token with explicit `--pairing-qr` (private local page) or `--show-pairing` (prints secret; never use in shared logs). Prefer supplying an in-memory environment token when the MCP adapter needs the same credential. No token stored on disk. Public/non-private cleartext URLs are rejected by Android.

QR pairing is a form-fill operation, not authorization. Payload: `phonebridge://pair?v=1&endpoint=<URL-encoded ws/wss /device URL>&token=<base64url secret>`. Exactly one of each key is required. Native endpoint/transport validation and user consent still apply. `PHONEBRIDGE_DEVICE_URL` optionally overrides the advertised endpoint for DNS/TLS deployments. `--pairing-qr` starts a separate loopback-only HTTP page at a random capability path, with exact Host validation, no foreign Origin, no caching and no framing. After five minutes the page returns 410; this hides the QR without revoking the Hub token. Stop the Hub or change its token to revoke a copied QR.
